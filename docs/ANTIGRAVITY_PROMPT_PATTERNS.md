# PROMPT — AUTO CHART PATTERNS ON EXISTING CHARTS (branch v1)

Add automatic pattern detection and drawing (trendlines, horizontal breakouts, triangles, base + pivot) to the **existing stock charts**, daily timeframe only. It works for ANY stock whose daily candles the chart already has (Screener chart, Chart View grid tiles, Sector stock detail panel). No new tab, no new DB table, no pipeline step, no network call: detection is pure JavaScript on the candles already in the browser.

Before you start: `git pull origin v1`. If the Tab 3 Round 2 work (commit `531a390` / `a25c053`) is not on `origin/v1` yet, push it first as its own commit. Do not mix it with this work. Commit this in phases `feat(patterns): P<n> ...`, push to `v1`, report the hashes.

## 0. Rules (non-negotiable)
- **Real data only.** Detection runs on real candles. Test fixtures may be synthetic and must be labelled `SYNTHETIC TEST INPUT`; no synthetic data ever reaches the UI.
- **A finder, not advice.** The output names a pattern and where the close sits against its line. It must NOT produce a score, grade, probability, target, entry, stop, "buy/sell", "bullish/bearish signal" wording. A test scans all generated text for banned words (`buy, sell, target, stop, entry, signal, score, probability, guaranteed`) and fails on a match.
- **Own code, own wording.** The reference site (scansutra.com) blocks automated reading, so the rules below come from the six reference screenshots and standard technical-analysis geometry. Do not copy any site text, name, logo or layout; write original explanations.
- Free tier only, no new dependency (use the installed `lightweight-charts` 5.3.0). Do not touch Breadth, Screener results, `SCREENER_PARAMS`, or any pipeline code. The existing `near_pivot` / `ipo_base` screeners are unchanged; the "Base + pivot" pattern here is a chart-drawing aid, it must not claim screener membership.
- Import everything you use (CI has `no-undef`); `pytest`, `npx tsc --noEmit`, `npx eslint .`, `npm run test:js`, `next build` must all pass.

## P1 — Detection library (`src/lib/patterns/`)
Files: `params.js` (ONE `PATTERN_PARAMS` object, every threshold named and commented), `atr.js`, `pivots.js`, `horizontal.js`, `trendlines.js`, `triangles.js`, `base.js`, `explain.js`, `index.js` exporting `detectPatterns(candles) -> { patterns, reason }`.
- **Input:** chronological daily candles `{date, open, high, low, close, volume}` (split-adjusted already). Drop rows with null OHLC. Fewer than 60 usable bars → `{ patterns: [], reason: "insufficient_history" }`. Look back at most 250 bars. Deterministic, no randomness, no `Date.now()`.
- **ATR:** Wilder ATR(14). All distances are in ATR units, so rules scale across prices.
- **Pivots:** a swing high at bar i if `high[i]` is the maximum of bars `i-k..i+k` (default k=3) and exceeds its neighbours' extremes by at least 0.5 ATR; swing low is symmetric. A pivot is **confirmed only k bars later**: the last k bars never serve as a touch (no look-ahead). Test this.
- **Geometry is done in ln(price)** so lines are correct on log and linear scales. Store each line as bar indices + prices; the renderer samples it (see P3).
- **Common line rules:** a *touch* is a swing point within `touch_tol` (default 0.35 ATR) of the line. A line needs ≥ 2 touches at least 5 bars apart. Between the first touch and the breakout, no close may be beyond the line by more than 0.2 ATR (a line already broken earlier is not drawn as "forming"). Span: 10–120 bars.
- **Horizontal ceiling / floor** (`horizontal.js`): cluster swing highs (lows) whose prices are within `touch_tol` of each other; line level = median of the touches. Status: `forming` (last close is below the ceiling by more than 0.5 ATR), `at_line` (within 0.5 ATR; shown to the user as **"Testing"**, and on the price axis as "Now · testing resistance/support"), `broke_out` (a close above level + 0.1 ATR after the last touch; for floors `broke_down` below level − 0.1 ATR). After a break record events: **breakout** (first close beyond the line), **retest** (a later bar whose close or low returns within 0.25 ATR of the line), **close_back_inside** (a later close back on the original side). Metric: `atr_beyond = (last_close − level)/ATR` signed. 
- **A "ceiling" can be sloped.** A real-chart sample (ABCAPITAL, daily, 4 touches) was a rising resistance line (about 407 -> 422 over 55 sessions) labelled "Ceiling x4 - Testing", with a pivot (420) and a base low (395.35) drawn as horizontals extended to the right. So treat the flat ceiling and the sloped resistance line as the same family: flat is just slope ~ 0. Draw touch circles at the TRUE swing price (not snapped onto the line); the small gap to the line is honest and must stay visible.
- **Sloped trendlines** (`trendlines.js`): resistance from swing highs, support from swing lows, any slope within `max_slope_pct_per_bar` (default 1.0% per bar in ln space). Enumerate pairs of swing points (cap 30 points per side), build the line, count touches among the other swing points, reject lines pierced between the two anchor points by more than `touch_tol`; keep the best per side by (more touches, then longer span, then fewer near-pierces). Same status/events logic as horizontals, measured against the line value at each bar. Touch count is shown (e.g. "resistance ×4").
- **Triangles** (`triangles.js`): an upper line and a lower line, each with ≥ 2 touches, converging (width at the end ≤ 0.6 × width at the start), duration 15–120 bars, price inside at the last touch. Ascending = flat upper (|slope| ≤ `flat_slope`) + rising lower; descending = flat lower + falling upper; symmetrical = falling upper + rising lower. Breakout/breakdown = close beyond the relevant line by 0.1 ATR, with the same retest events. Reuse the horizontal and trendline primitives; do not duplicate the geometry.
- **Base + pivot** (`base.js`): a *leg start* = a swing low followed by a rise of at least `leg_min_rise_pct` (default 20%) within 60 bars; the *pivot* = the highest high of the leg; the *base* = the consolidation after that high lasting 5–40 bars with depth `(pivot − base_low)/pivot ≤ base_max_depth_pct` (default 35%); *base low* = lowest low in the base. Status `forming` (close ≤ pivot) or `broke_out` (close > pivot + 0.1 ATR). Output: leg-start point, pivot line, base-low line, base box (start/end bars). Volume ratio of the break bar vs 50-bar average is reported as a plain number, never as a grade.
- **Pattern object** (stable schema, documented in a header comment): `{ id, type, side, status, title, lines: [{role, idx1, p1, idx2, p2, touches:[{idx,price}]}], band: {half_width_atr}, base_box?, events: [{type, idx, date, price}], window: {start_date, end_date, found_date}, metrics: {touches, atr_beyond, span_bars, volume_ratio?}, summary, rule_text }`.
- **Ordering and caps (not a score):** (1) patterns with an event or `at_line` in the last 3 bars first, (2) more touches, (3) longer span. Return at most 8 patterns; at most 1 per (type, side, overlapping window); if two patterns share ≥ 70% of the same line, keep one.
- **Text** (`explain.js`): original plain-English templates, e.g. title "Ascending triangle", summary "Pattern 14 Oct 2026 to 18 Nov 2026, found 20 Nov 2026. The last candle closed 0.58 ATR above the line.", rule_text one or two sentences describing the rule. Dates formatted `D Mon YYYY`. Never use banned words.
- **Performance:** ≤ 15 ms per stock for 260 bars (measure in a test and print it; assert ≤ 60 ms to avoid CI flakes).

## P2 — Tests (`tests/test_patterns.mjs`, add to `npm run test:js`)
Synthetic labelled fixtures built deterministically (seeded generator): flat ceiling with 3 touches then breakout; same without breakout (`forming`, then `at_line`); breakout then retest then close back inside; rising support line with 3 touches then a break down; falling resistance with 4 touches; ascending, descending and symmetrical triangles with breakout; leg + base + pivot with and without breakout; insufficient history; null OHLC rows dropped. Invariants over 200 seeded random walks: every returned touch is within `touch_tol` of its line, no line is pierced beyond tolerance between anchors, every date is inside the series, no touch falls in the last k bars, output is identical on repeated calls, text contains no banned word, runtime bound. Also test that adding bars to the END does not change touches that were already confirmed earlier.

## P3 — Drawing (`src/components/charts/patternLayers.js` + integration)
- Implement one `lightweight-charts` series **primitive** (`attachPrimitive`) that draws, in pixel space from logical bar indices (`timeScale().logicalToCoordinate`) and `series.priceToCoordinate`: (a) the main line as a polyline sampled every 4 bars (so a ln-space line stays correct on a linear scale), solid between the anchors and **dashed beyond the last anchor, extended 15 bars forward** (works without whitespace data); (b) the **retest band**: a light translucent fill ± `half_width_atr`; (c) small open circles on the touch points; (d) event glyphs: **filled dot** at the breakout close, **ring** at a retest, **cross** at a close back inside; (e) the base box (light fill) with the pivot line (dashed, labelled "pivot") and base-low line (dashed, labelled "base low"), both starting at their anchor bar and **extended to the right edge** and an up-arrow with "leg starts". Colours come from the existing tokens/`chart-theme` (resistance/broken-up = bearish red line as in the reference, support/broken-down = blue, base items = primary), light and dark, never colour alone (labels and glyph shapes carry the meaning).
- Price-axis tag for the active line side, e.g. "Resistance ×4" (text only, same style as the existing level tags). "Now" tag unchanged.
- **Layers chip row** at the top-left of the chart, each chip with a live count and a toggle: `Pattern lines n`, `Breakout + retest n`, `Base + pivot n`, `21 EMA` (reuse the existing EMA drawing). Default: top 3 patterns on. A muted "◂ N earlier" label at the left edge when a pattern's anchors begin off-screen.
- **Integration:**
  1. `ScreenerChart.jsx`: add the layers above, wired to `detectPatterns(candles)` in a `useMemo`. Daily only: on the weekly timeframe the pattern layers are disabled with the tooltip "Patterns are daily only". Do not disturb the existing rules overlay (`stockData.overlay`) or its markers.
  2. Sector stock detail panel (Tab 3 chart): same component/layers via the shared code. No duplicate implementation.
  3. Chart View grid tiles (`ScreenerGrid.jsx`): draw only the top-ranked pattern's main line + band and a small status text on the tile header (e.g. "Ascending triangle · Broke out"). Detect once per tile with `useMemo`; 40 tiles must not make the grid sluggish (report the measured total time).
- Primitives and listeners are detached in the effect cleanup; no leaks when switching stocks or toggling layers; no animation.

## P4 — Pattern panel under the chart (Screener chart and Sector detail)
- A header block: pattern title, status chip (`Forming`, `At the line`, `Broke out`, `Broke down`), facts line (window, found date, `atr_beyond`), the `rule_text`, and a muted legend ("Red: line broken upward; blue: line broken downward; grey wash: retest band; small circles: swing points; filled dot: breakout close; ring: close back at the line; cross: close back inside").
- "Other patterns on this chart" chips; clicking one makes it the focused pattern (its line is drawn solid and thick, others thin).
- Footer, exact: `Pattern finder only. It names a pattern and where the close sits against its line. It gives no score, target, entry or stop.`
- Empty state: "No pattern found on the daily chart" with the reason (`insufficient_history` → "Not enough daily history").
- Phone: the panel stacks under the chart; chips scroll horizontally; chart height unchanged.
